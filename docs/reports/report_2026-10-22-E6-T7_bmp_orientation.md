# Отчёт шага E6.T7 — контракт ориентации кадров (BMP)

**Дата/контекст:** фаза Implementation, роль dev→QA. Git: коммит `img.h`/`img.c`/`main.c` + документы.

## Цель

Проверить гипотезу пользователя: «GL рендер выдаёт правильно, но ломается в моменте сохранения в BMP»
— то есть разобраться, почему `hud_frame.bmp` выглядит перевёрнутым по вертикали, и зафиксировать
орентацию кадров так, чтобы она проверялась числами, а не «на глаз».

## Как проверено (фактический вывод)

1. Зонд ориентации на байтах файла (BMP хранит BGR):

```
make -s trash/probes/probe_img.exe
./trash/probes/probe_img.exe
top-down rgba (row 0 = top): file row 0 (image bottom in file) = 0,0,255 ; display top = 255,0,0 -> PASS
GL order rgba (row 0 = bottom): file row 0 (image bottom in file) = 255,0,0 ; display top = 0,0,255 -> FAIL
probe: FAIL   (ожидаемо: второй случай доказывает переворот при GL-порядке входа)
exit=1
```

Вывод: писатель BMP корректен (BGR, padding, размеры, bottom-up DIB); переворот возникает, когда
вызывающий передаёт строки в GL-порядке — ровно то, что обещал старый текст `img.h`.

2. Продукт, полный прогон:

```
make clean && make        → сборка без warning'ов (gcc 14.2.0, -O2 -std=c11 -Wall -Wextra)
./viewer.exe --selftest   → ok=26, FAIL=0, "selftest: PASS", exit=0
  в т.ч.: ok  BMP orientation: first rgba row lands on top of the image
powershell -File tests/run_tests.ps1 → ok=59, FAIL=0, "tests: PASS", exit=0
python ... out_teapot.bmp → ink rows 183..445 из 600 (кадр в кадре, ориентация не «съехала»)
```

3. Регрессия не ослаблена: все прежние пороги (coverage, outline-пиксели, коды возврата на плохих
входах) прошли без изменений.

## Диагноз пользовательского наблюдения

`hud_frame.bmp` выглядел «перевёрнутым/отзеркаленным» не из-за записи BMP и не из-за GL:
- ориентация продукта верна (доказано п.1/п.2);
- в зонде HUD глифы семплировали один текстурел (плоские плашки), а диагностические вызовы в
  hidden-window зонде сами ненадёжны (§2 памяти). Визуальная оценка «весь файл перевёрнут» была
  следствием сочетания этих двух эффектов в зонде + двусмысленного контракта `img.h`.
