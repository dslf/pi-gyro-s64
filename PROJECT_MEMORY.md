# PROJECT_MEMORY.md — Память проекта

**Назначение:** глобальный технический контекст. Один источник правды для архитектуры, стека,
принятых решений и особенностей окружения. Обновляется после каждого утверждённого этапа
(после одобрения пользователем; авто-коммиты запрещены).

---

## 1. Что это за проект

Десктопный 3D-вьюер форматов `.obj` (позже `.mtl` + текстуры): загрузка модели, вращение/пан/zoom
мышью, рендер в окно OpenGL 4.6 core, сохранение кадра в файл, headless-режим для тестов.

**Код:** `src/` (C11), `shaders/` (GLSL), `tests/` (PS1 + Python), `Makefile` (сборка одной командой).
Корень: `P:/vibeshe2/Opencoder/pi/pi-gyro-s64`.

## 3. Архитектура (текущая база)

- `obj.c` — парсер OBJ: все формы граней (tri/quad/poly), отрицательные и relative индексы,
  `vt`/`vn`, отсутствие `vn` → нормали вычисляются локально, `p`-точки игнорируются,
  авто-определение up-axis, авто-масштаб/центрирование по bounding radius.
- `vmath.c/h` — свои `mat4/vec3/mat3`: `m4_perspective`, `m4_ortho`, `m4_map_point`, `m3_normal`.
- `gl.c/h` — ручной загрузчик GL (~50 слотов): `glfwGetProcAddress` → `wglGetProcAddress` → `opengl32.dll`.
- `camera.c/h` — orbit-камера: yaw/pitch/dist/fov/ortho; framing по bounding sphere с учётом аспекта;
  near/far “обнимают” модель (`dist ± fit`) — иначе perspective и ortho расходятся по глубине.
- `mesh.c/h` — загрузка VBO/VAO на GPU + хранение CPU-версий (`cpu`) для picking/подсветки.
- `render.c/h` — Blinn-Phong, двустороннее освещение, gamma, wireframe, offscreen FBO,
  **подсветка выбранной грани** (отдельный VBO с barycentric-attribute, без геометрии в 2×).
- `img.c/h` — BMP 24bpp из FBO: вход — строки сверху вниз (`rgba[0]` = верх кадра, как возвращает
  `render.c:fb_read_rgba`); файл пишется как bottom-up DIB (строки переворачиваются при записи).
  Контракт зафиксирован в `img.h` и подтверждён численно (selftest + CPU-зонд).
- `main.c` — CLI (`--render`, `--selftest`, `--wire`, `--ortho`, `--fov`, `--yaw`, `--pitch`, `--size`),
  интерактив (LMB orbit, RMB pan, wheel zoom, Ctrl+wheel fov, O/W/R/S/Esc), `pick_triangle()`,
  самодостаточные selftest-ы (26 проверок, все зелёные; блок `BMP orientation` проверяет ориентацию
  кадра по известным цветам верхнего/нижнего ряда).

## 4. Принятые решения (ADR-краткая форма)

1. **C + OpenGL 4.6 core, без внешних библиотек кроме GLFW** — сборка одной командой, reproducibility.
   Переход с 3.3: 4.6 — последняя стабилизированная core-версия; шейдеры `#version 460 core`.
   Контекст создаётся без `GLFW_OPENGL_FORWARD_COMPAT`: в 4.6 GL 1.1-функции из `opengl32.dll`
   адресуют generic-реализацию, поэтому диагностика атрибутов в hidden-window зондах ненадёжна
   (§2). Переход подтверждается числами: `GL  : 4.6.x …`, `selftest: PASS`, `tests: PASS`.
2. **Своя математика** вместо cglm — ~100 строк, ноль зависимостей, полный контроль над ortho/persp.
3. **Освещение Blinn-Phong** (не PBR) — достаточно для вьюера; PBR отдельным этапом.
4. **Подсветка selected triangle вне main VBO** (barycentric + `uHighlight`) — main-буфер не меняется
   при выборе; снятие выбора = один uniform, не пере-загрузка геометрии.
5. **Глубина picking = monotone NDC z** (`m4_map_point`) — одинаково работает в perspective и ortho;
   nearest wins независимо от порядка треугольников в файле.
6. **Конвенции мыши проверяются, а не угадываются**: сравнение проекций граней до/после drag.
7. **Тесты = selftest (C) + регрессия (PS1/Python)**: и геометрия, и пиксели, и коды возврата.
8. **Ориентация кадра — контракт, а не предположение**: пиксели от `fb_read_rgba` идут строками
   сверху вниз (`row 0` = верх), `img_write_bmp` принимает этот порядок и сам переворачивает строки
   при записи bottom-up DIB. Прежняя формулировка в `img.h` («row 0 = bottom») была обратной и
   порождала перевёрнутые кадры у вызывающих (то же проявилось в зондах). Ориентация закреплена
   численным selftest'ом и CPU-зондом, чтобы не зависеть от субъективной оценки «картинка перевёрнута».
9. **VCS-раскладка**: трекаются только продукт и документы — `src/`, `shaders/`, `assets/`,
   `tests/*.ps1|*.py`, `Makefile`, `PLAN.md`, `PROJECT_MEMORY.md`, `Roadmap.md`, `AGENTS.md`,
   `.obj`-ассеты. Бинарники, кадры, зонды, `node_modules/` — исключены.
10. **Вывод тестов — в `tests/out/`** (git-ignored): регрессия больше не пишет BMP в корень;
   каталог очищается перед каждым прогоном, файлы остаются для визуальной проверки.
11. **Большие правки выполняются частями** (запрос owner, лимиты в токенах): жёсткий лимит длины
    ответа — 8192 токена; «большая правка» = правка ≥ 4096 токена. Целевая длина одной генерации
    1–2k токена, запас 1–2k держится постоянно. Large rewrite запрещается как один вызов: файл
    пишется секциями (несколько `edit`/`append`), правки идут последовательными шагами, каждый шаг
    проверяется до следующего. План частей объявляется до первой правки.
12. **Dear ImGui через cimgui как vendored статическая библиотека** (запрос owner). Продукт остаётся
    C11: C++ части (imgui + cimgui + бэкенды GLFW/OpenGL3) собираются отдельным скриптом в
    `deps/imgui/libcimgui.a`, продукт линкует её и вызывает только C-API (`cimgui.h`). Оверхед
    компиляции C++ изолирован от `src/`, warning'ов продукта это не касается. Лицензия MIT.
    Версии фиксируются коммитом (cimgui `2a6a93f`, imgui `6d321745` = 1.93.0 docking).
13. **HUD текста — ImGui, GDI-атлас уходит из продукного пути.** Причина: ImGui даёт
    антиалиасинг и читаемый масштаб (продукт на FBO 560×240 при scale 1.0: контраст 6.51:1 для
    панели статистики и 6.47:1 для панели подсказок после смешивания фона с AA; короткие штрихи
    1101 и 1490 против длинных 0 и 3), плюс FPS/подсказки/будущие виджеты без своего atlas-кода.
    HUD разделён на две панели: **статистика** (fov, dist, проекция, FPS, triangles, выбор, wireframe)
    в левом верхнем углу, **подсказки горячих клавиш** внизу по центру; размеры считаются из текста,
    ширина подсказок ограничена `HUD_HELP_W` (по умолчанию 760 px), поэтому текст переносится
    на узких окнах вместо обрезки. HUD-окна читают только информацию: флаги `NoInputs`/`NoMove`/
    `NoTitleBar` — мышь и клавиши вьюера не перехватываются. Оверлей остаётся только в
    интерактивном кадре (`app.hud_overlay`), offscreen/selftest-кадры без HUD. Проверка HUD в
    selftest — пиксельные метрики ImGui по rect'ам обеих панелей (`hud_rect(panel)`): позиция
    каждой панели, центрирование подсказок, чернила, контраст WCAG, структура штрихов, отсутствие
    чернильных пикселей вне панелей, зазор между панелями, детерминизм повторного кадра и
    перенос подсказок на узком кадре (420×320).

14. **Resize окна перерисовывается сразу, не после конца drag'а.** Размер цели
кадра не кэшируется из callback'а: `sync_framebuffer_size()` каждый кадр читает
`glfwGetFramebufferSize` и обновляет viewport/аспект/HUD до отрисовки. Дополнительно
регистрируется refresh-коллек: на Windows перетаскивание границы держит модальный
цикл сообщений, где наш игра-луп не получает ничего, и единственный способ нарисовать
новый клиент — перерисовать в коллеке на WM_PAINT (`draw_scene` + `glfwSwapBuffers`).
Ответственность остаётся в `main.c` (`sync_framebuffer_size`, `on_refresh`); камера
по-прежнему получает аспект из размера цели в `draw_scene`.

15. **Публичный репозиторий** (`dslf/pi-gyro-s64`, public, branch `main`): в git только источники —
    `src/`, `shaders/`, `tests/`, `assets/` (включая `utah_teapot.obj`, переименован из
    `utah-teapot.obj` ради ASCII-путей в зондах), `lab/probes/` (зонды как документация разработки,
    их артефакты игнорирует `lab/.gitignore`), `deps/imgui` (источники MIT; `deps/imgui/build` не в git),
    `docs/viewer-window.png` (исключение из `*.png`), README, LICENSE (MIT), Makefile,
    AGENTS/PLAN/Roadmap/PROJECT_MEMORY. `trash/` не публикуется. На чистом клоне нужно
    `make imgui` (статическая `libcimgui.a` не в git) и статический GLFW в тулчейне.

16. **Идентификация грани живёт в `obj`, не в `main`.** `obj_mesh` хранит `face_ids` (ordinal
авторской грани) и `vert_ids` (1-based номера вершин из `f`-строки); наружу отдаёт
`obj_triangle_identity`, `obj_face_normal`, `obj_vertex_normals`, `obj_normal_deviation_deg`.
`main.c` показывает эти значения в HUD и stdout и не считает номера грани по номеру
треугольника. Отклонение нормалей вершин от нормали грани — **оценка, не факт файла**: когда
`vn` нет, все три нормали вершин равны нормали грани, и строка HUD говорит об этом прямо.

17. **Tab шагаёт по граням в порядке файла, `R` снимает pin.** `face_step(cur, total, dir)` —
чистая функция с циклическим шагом (`-1 → 0` вперёд, `0 → total-1` назад), проверяется
selftest'ом без окна; шаг печатает номер грани, номера вершин и нормаль грани в stdout (то же,
что видно в HUD). `R` кроме reset камеры снимает pin и hover: кадр после reset не держит
старое selection. Подсказки в help-панели и таблица hotkeys в README — это **реальный кэймап**
`src/main.c`, а не желаемый список: `Ctrl+wheel` и `[ ]` меняют viewing angle (не дистанцию),
`O` — проекция, `W` — wireframe overlay, `S` — screenshot.

18. **`README.md` — публичное описание репозитория, а не инструкции.** Это витрина
    `dslf/pi-gyro-s64`: что это, как выглядит, как собирается и запускается, чем проверяется.
    Регламент и роли — в `AGENTS.md`, решения — в `PROJECT_MEMORY.md`, статусы — в `Roadmap.md`;
    в README они не дублируются. README правится в том же коммите, что меняет поведение (hotkeys,
    CLI, команды сборки, версии стека), числа берутся из фактического вывода команд; расхождение
    «README ≠ код/вывод» — defect по AGENTS.md §0.8 (исторический пример: README описывал `L`,
    `LWin+W`, `T`, `P`, `H`, `--shot`, которых в продукте нет). Состав секций и проверка после
    правки — AGENTS.md §6.

20. **Бинарь продукта — в корень проекта; `build/` заморожен как scratch (решение owner'а,
    2026-10-22).** `make` again собирает `viewer.exe` в корень, запуск и регрессия —
    `./viewer.exe`, пути к `assets/` и `shaders/` снова относительно корня (запуск из корня
    репозитория). `build/` не используется для бинаря продукта и остаётся ignored; внутри него
    допустимы временные файлы сборки (`*.o`, промежуточные артефакты) если они понадобятся.
    Причина отмены: перенос бинаря сломал запуск из корневого cwd — `pick_default_model()` и
    шейдеры резолвятся относительно cwd, и `./viewer.exe` (привычная команда) перестал существовать.
    Остальная часть ADR 19 остаётся в силе: отчёты шага в `docs/reports/` (трекаются),
    вывод регрессии в `tests/out/`, зонды в `lab/`, scratch в `trash/`.

21. **Настройки через ImGui-виджеты, `settings.ini` рядом с бинарём (запрос owner, 2026-10-23).**
   Единый источник правды — таблица дескрипторов `SETTINGS_FIELDS[]` в `src/settings.c`: ключ ini,
   подпись виджета, тип, кламп, дефолт. Из одной таблицы генерируются и виджеты
   (слайдер / drag / чекбокс), и сериализация ini, и сверка парсера — ключ не может
   «потеряться» или разъехаться при расширении (24 ключа). Формат ini: `key = value`; пустые
   строки и `#`-комментарии игнорируются; неизвестный ключ или битое значение — предупреждение с
   именем ключа и номером строки и дефолт (не fatal, интерактив продолжает работать); значение
   вне диапазона — кламп с печатью числа. Файл лежит в корень репозитория (`settings.ini`, git-ignored, рядом с
   `viewer.exe`) — решение owner'а.
   Чтение только в интерактиве: `--render` и `--selftest` остаются на встроенных дефолтах, иначе
   пиксельные метрики регрессии перестают быть детерминированными. Порядок приоритетов:
   дефолт кода < `settings.ini` < env (`HUD_FONT_SCALE`, `HUD_W`, `HUD_HELP_W`). Явного CLI-флага
   для файла настроек пока нет — путь один, корень cwd.
   Виджеты берут мышь: панель настроек рисуется **без** `NoInputs`, и мышь вьюера гейтится по
   rect'у панели (`hud_settings_grabbed`) — drag, hover-picking и pick над панелью не срабатывают,
   `Esc` работает всегда. `io->WantCaptureMouse` не используется: он правдив только после
   `igNewFrame`, а обработчики мыши вьюера живут в callback'ах GLFW, которые приходят раньше.
   Панель статистики и подсказки остаются read-only и не двигаются; подсказки при нехватке места
   теряют хвостовую строку (`hud_hint_lines`), карточка статистики не перекрывается.
   Свет/фон/поверхность/небо/контур подаются через `renderer_set_*` (`src/render.c`) как uniform'ы,
   математика камеры — в `camera.c` (`camera_view_angle_deg`, `camera_ortho_scale`,
   `camera_zoom_abs`), в `main.c` остаётся только wiring (AGENTS.md §2).
22. **Контракт ImGui `Begin`/`End` в `hud.c`: `igEnd()` вызывается всегда** (решение owner'а после
   краша 2026-10-22). При свёрнутой панели (треугольник в заголовке, или `Tab` над ней) и при
   скрытой панели `igBegin` возвращает false — окно не открыто, но стек ImGui ждёт `igEnd`, иначе
   `Assertion failed: (0) && "Missing End()"` в `imgui.cpp:11325` и `abort()`: сворачивание настроек
   роняло интерактив. Раньше три места `hud_draw` (панель настроек, карточка статистики, подсказки)
   выходили из блока по `if (!igBegin(...)) return;` без `igEnd` — теперь структура
   `if (igBegin(...)) { ...содержимое... } igEnd();`; содержимое читает `igItemRect`/`igWindowRect` и
   пишет мышь-гейт только когда окно реально открыто. Численная проверка в разделе `settings.ini`:
   кадр со свёрнутой панелью до (`rect 460 x 679 px`) и после (`tab 460 x 23 px` в тех же координатах,
   `mouse over the tab 1`) — вкладка остаётся под курсором, процесс не абортится; затем unfold
   возвращает `rect 460 x 679 px`. Проверка воспроизводит баг в headless (`--selftest`).
   Дополнительно: таблица hotkeys в `README.md` обязана быть копией `grep GLFW_KEY_ src/main.c` —
   в таблице жила строка «`/shees` — перечитать `settings.ini`», которой в коде нет (такого
   хоткея никогда не было; перечитать файл можно только перезапуском). Строка убрана, добавлены
   `H` и `Tab`-над-панелью. `settings.ini` добавлен в `.gitignore` как артефакт рядом с бинарём.
23. **Мышь панели настроек: ownership у HUD, а не у rect'а** (фикс 2026-10-22 по трём жалобам
   owner'а). Гейт в `main.c` (`mouse_in_settings`) смотрел только на rect панели, поэтому
   (а) drag ползунка/scrollbar'а за пределами окна отдавал движение камере — модель начинала
   вращаться; (б) колесо над панелью не прокручивало список — на окне висел
   `ImGuiWindowFlags_NoScrollWithMouse`, а wheel в `handle_scroll` всегда шёл в зум; (в) панель
   нельзя было двигать за заголовок — `hud_frame` каждый кадр форсил позицию с
   `ImGuiCond_Always`, что отменяет move ImGui (применяется в `NewFrame` до нашего `Begin`).
   Теперь: `mouse_in_settings` = rect **или** активный ImGui-gesture (`hud_mouse_busy` →
   `igGetActiveID() != 0`: перетаскивание виджета/scrollbar'а/заголовка держится до отпускания
   кнопки, выход курсора за окно его не сбрасывает); флаг `NoScrollWithMouse` снят, wheel над
   панелью остаётся ImGui; позиция форсится только до первого захвата панели (`settings_placed`)
   или когда `hud_settings_place` вызван явно (правый drag по панели меняет ширину). Позиция
   читается из окна обратно в `settings.ini`, поэтому drag за заголовок переживает перезапуск.
   Меряется инъекцией событий (`hud_warp_mouse`) — см. §5 M13.1. Проверка wheel требует кадр
   hover'а перед шагом: ImGui маршрутизирует колесо по `g.HoveredWindow`, который считается в
   `EndFrame` предыдущего кадра.

- **Крупные стресс-фикстуры не публикуются** (owner'ское решение 2026-10-22):

  Сообщение usage «put an .obj next to the exe» описывает поведение, которого в коде нет —
  это defect (ADR §18 правило «README/usage ≠ код»).

- **Формат**: только `.obj` или также `.glb/.gltf`? (glTF потребует свой парсер или vendored `cgltf`).
- **MTL/текстуры**: нужен `stb_image.h` (vendor, один header) или свой minimal PNG/JPEG декодер?
- **Git**: локальный репозиторий + remote `dslf/pi-gyro-s64` (public, branch `main`). Push —
  только по явному одобрению owner; политика «что трекается» в ADR §15.
- **Артефакты вне VCS**: политика зафиксирована — вывод тестов в `tests/out/`, зонды в `trash/`;
  новые пробы не должны появляться в корне или в трекаемых каталогах.
- **HUD on/off и отдельная клавиша снятия pin**: видимость панелей статистики и подсказок
  решается **виджетом** в панели настроек (checkbox «info panels»), новой клавиши в продукте нет —
  таблица hotkeys в README от этого не меняется (ADR §4.21). Отдельная клавиша «release pin»
  остаётся 🔵: повторный click на той же грани и `R` уже снимают pin, новый ключ меняет README
  и текст help-панели.
- **HUD (E5.T1/E5.T4/E5.T5/E5.T6)**: основа — Dear ImGui (ADR §12/§13). Две панели, каждая
  **облегает текст по обеим осям** (`ImGuiWindowFlags_AlwaysAutoResize`, ширина и высота не
  задаются вручную; `SetNextWindowSize` с компонентом 0 не считается «заданной из API» —
  `deps/imgui/imgui/imgui.cpp:7742`), поэтому пустых строк и полей нет. Позиция задаётся
  пивотом: статистика — левый верхний угол (`pivot 0,0`, margin 8), подсказки — низ по центру
  (`pivot 0.5,1.0`, нижний край на margin 8). Пустое место ловится selftest'ом: bounding box
  чернил обязан доходить до краёв панели — зазоры ≤14 px (лево/верх/низ), правый край подсказок
  ≤80 px (это slack переноса строки, не пустая строка). `NoInputs`, font scale 1.0, тёмный фон
  WindowBg (0.08,0.10,0.14,0.94) + яркий текст (0.95,0.97,1.00): контраст после смешивания фона
  и AA 6.51:1 (stats) и 6.47:1 (help) при запрошенном 16.39:1. Стиль плотный: без рамки,
  rounding 4, padding 8×6, ItemSpacing 0×2.
  Env-подбор профиля без пересборки: `HUD_FONT_SCALE`, `HUD_W` (пинит ширину панели статистики,
  по умолчанию 0 = авто), `HUD_HELP_W` (лимит ширины подсказок, по умолчанию 760 px);
  `HUD_H`/`HUD_HELP_H` убраны — высота считается из текста.
  `DisplaySize` задаётся явно (offscreen-рендер в selftest), warm-up ≥ 3 кадра до пиксельной
  метрики (атлас строится на `EndFrame`). Третья панель (виджеты, E5.T7) не auto-fit по
  ширине: ширина пиновается из `settings_w` (дефолт 460 px — при 320 px подписи виджетов
  обрезались), высота ограничивается местом между карточкой статистики и подсказками,
  переполнение достается scrollbar'ом (`NoScrollWithMouse` — колесо остаётся зумом),
  на узком кадре панель не рисуется вовсе. Оверлей рисуется **только в интерактивном кадре**
  (`app.hud_overlay`) — offscreen `--render` и кадры selftest без HUD, иначе метрики силуэта
  загрязняются. Ширина подсказок ограничена, поэтому resize переносит текст, а не обрезает:
  selftest меряет кадр 960×320 и узкий 420×320, обе панели внутри кадра, чернила вне панелей
  0 px, штрихи 1101/0 и 1490/3, детерминизм 0 px.
  Интерактивный цикл рисует **каждый кадр** (`glfwPollEvents`, без гейта по `dirty`), поэтому HUD
  обновляется и в простое: на 170 Гц мониторе замерено 501 кадр / 3.00 с = **170 fps**
  (`./viewer.exe assets/utah_teapot.obj --idle-report 3`). `fps` считается как кадры за окно 0.5 с
  (EMA по dt завышал цифру, когда ОС будит цикл раньше). `dirty` остаётся только для обновления
  заголовка окна. Искусственный троттлинг не добавлялся: реальную частоту задаёт vsync/GPU.
- **Сборка ImGui**: требует `g++` + `ar` и линкует `-lstdc++ -static-libgcc -static-libstdc++`.
  Продакт остаётся C11 (вызывает только `cimgui.h`). `deps/imgui/build/` и `lab/imgui/cimgui/`
  (vendored клон для зонда) — git-ignored; чистый clone собирает библиотеку сам, но зонд `lab/imgui`
  требует повторного клона cimgui.
- **Отчёты шага**: публикуются в `docs/reports/report_YYYY-MM-DD-<task>.md` (трекаются, ADR §4.19);
  рабочий scratch/harness-лог остаётся в `trash/logs/` (git-ignored, не публикуется).
- **Бинарь продукта**: `viewer.exe` в корне (git-ignored, создаётся `make`) — ADR §4.20 отменил
  перенос в `build/`. `build/` остаётся git-ignored scratch: только временные файлы сборки
  (`*.o` и т.п.), бинаря продукта там нет. Расхождение зафиксировано в §6 (owner'ское решение
  против ADR 19), не «чинится» молча.
- Явного CLI-переопределения up-axis нет: ось определяется по bbox в `obj.c` и нормализуется в
  +Y; `--up <axis>` отсутствует в `usage`, selftest-блок на X-up/Z-up фикстурах не написан —
  E1.T6 🟡, 🔵 ждёт решения owner.
- **Машинные зависимости**: Windows-only (opengl32/wgl). Кроссплатформенность не проверялась.
- **Производительность**: picking = CPU-обход всех треугольников на каждый hover. Замерено
  (`lab/probes/probe_bigobj.c`, фикстура 2.26M tri): **39.9 ms** на hover-луч, 17.7 ms на 1M tri,
  худший 44.4 ms → при 2M+ граней hover не обновляется быстрее ~25 луч/с. Кадр при этом 23.7 fps
  (1280×900, MSAA 4), peak RSS 747–764 MB. Риск подтверждён числами: для 2M+ граней нужен
  BVH/облок (E3.T1 ⬜); память под 2.26M tri комфортна, парсинг 3 s — однократная стоимость загрузки.
- **Пиксельные тесты чувствительны к GPU** (антиалиасинг, gamma) — пороги задаются как относительные.
